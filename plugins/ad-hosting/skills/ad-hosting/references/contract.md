# Hosting contract 1.0.2

Fetch `campaign_hosting_guide` for the current complete template and conventions. This package also includes `template.json` and `schema.json`, generated from the maintained TypeScript schema. Prefer the hosted guide if the versions differ. Do not silently use new fields against an older server.

The semantic memo is interpreted by the assistant. The typed brief is validated and compiled by code. Save the entire preparation object, including unresolved nulls. The packaged JSON Schema describes structural shape; cross-field uniqueness, sums, chronology, IANA timezones and other semantic checks remain in the maintained Zod schema on the server. Passing a local JSON Schema validator alone does not establish a valid plan. No account credentials or raw lead records belong in it.

- `initiativeKey` groups related tests. `campaignKey` describes one saved test. `campaignId`, assigned by the server, is its globally scoped join.
- `productKey`, `audienceKey`, `conceptKey` and `variantKey` are explicit lowercase dimensions, 2–40 characters, using letters, digits and underscores. Case/punctuation variants are rejected rather than normalized into collisions. Confirm the meaning before first save.
- Unresolved initiativeKey, campaignKey and channel stay null until selected. Their first non-null values become fixed. Each ad `key` is unique within the saved campaign. Once saved, it cannot be removed or reassigned to a different concept/variant; retain it as excluded. Use a new campaign for a new initiative/campaign key or channel. This version does not adopt or relabel legacy live ads; flag a request to reuse an existing live ad's deployment identity for the future adapter rather than claiming adoption.
- `adKey` is a generated deployment join bound to campaign record ID, ad key, copy, CTA, exact rendition references, audience, countries, destination and experiment assignment. A material deployment change creates a distinct join. Title changes and ad array order do not change it. Names are readable labels, never joins inferred by parsing.
- Required `square`, `feed45`, `vertical`, `landscape` formats describe rendition coverage. Library dimensions must match their aspect ratios. The skill does not silently crop. Each ad holds at most one exact version per format; excluded ads do not count as active creative choices.
- `budget.amountMinor` and `ceilingMinor` use integer cents for supported CAD, USD, EUR and GBP. `type` is daily or lifetime at campaign level. A daily amount is not a total spending cap. Unsupported currencies or ad-set allocations need a contract extension, not an assumed conversion.
- Dates are explicit offset instants; timezone is an IANA account timezone. Missing dates can remain null during preparation. Never interpret a date in the assistant's timezone when the account differs.
- An experiment stores its kind, allocation and arms with integer weights totaling 100. Creative comparisons can use null arm destinations and the shared campaign destination; multi-arm creative comparisons require ad armKey assignments. For randomized page routing, the campaign destination is the shared entry route and the router assigns the page arm after the click. Native experiments require ad armKey and use that arm's destination. Landing-page arms require their destination URLs. `assignmentEvidenceRef` names real implementation/verification evidence; arbitrary text does not establish live correctness. The publisher must verify it.
- The compiler replaces existing `utm_*`/`yoke_*` values in the recommended URL, preserving other parameters and fragments. `utm_campaign` is the saved record ID; `utm_content` is `adKey`. `yoke_*` retains readable dimensions. It does not alter existing URLs or historical reporting. Routers must retain tags and record the experiment arm downstream.
- Library approval comes from the exact version's review. Preparation can expose unapproved assets for review; activation cannot infer approval from the packet. A new check may change manifestHash because approval/archival/readiness changed.
- External upload, attachment and verification are always `not_observed` here. Only the future trusted platform adapter can establish those states.

`campaign_prepare` returns `{manifest, csv, markdown, libraryCheckedAt}`. The manifest includes `compilerVersion`, `inputHash`, `planHash`, `manifestHash`, campaign ID/revision, labels, ads, media, exclusions, issues and remaining launch checks. The manifest hash is SHA-256 over the canonical manifest without its own hash field. The observation timestamp stays outside it. `ready_for_review` requires no preparation issues, while launch-only issues remain visible. `launchReady` is always false in this hosting release.

Writes use `campaign_hosting_save({campaignId, expectedRevision, requestKey, preparation})`. Readback is `campaign_get`, compilation is `campaign_prepare({campaignId})`. The personal API uses `/campaigns/<id>/commands` with `{expectedRevision,requestKey,command:{type:'save_preparation',preparation}}` and GET `/campaigns/<id>/preparation`.
